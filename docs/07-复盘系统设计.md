# 07 - 复盘系统设计

> 关卡结算后,玩家能进入复盘模式:拖时间轴回看整个操盘过程,看清"我在哪吸筹、AI 什么时候反击、机构 B 在什么位置减仓、散户何时恐慌"。
>
> **核心价值**:验证 AI 真的在博弈而非随机。没有复盘,AI 像随机数。

## 1. 设计目标

- **时间轴回放**:拖动到任意时刻,查看当时的盘口/持仓/成交/AI 独白
- **成交身份揭示**:盘中对玩家隐藏的"谁在买谁在卖",复盘时完全可见
- **AI 内心独白**:按时间轴回看 AI 每个决策点的状态/信号/理由
- **参与者视角**:各方的持仓/成本/权益随时间变化

## 2. 数据采集(ReplayCollector)

**文件**:`src/IamZhuli.Simulation/MarketData/ReplayCollector.cs`

### 2.1 关键帧快照(每 20 tick 存一次)

```csharp
public record ReplaySnapshot(
    int TickIndex,           // 全局 tick 序号(0~4499,30天×150tick)
    int Day, int TickOfDay,
    decimal Price,           // 现价
    decimal RegulatorHeat,   // 监管关注值
    List<(decimal Price, int Qty)> TopBids,    // 盘口10档(拷贝)
    List<(decimal Price, int Qty)> TopAsks,
    List<ParticipantState> Participants);      // 各方持仓状态
```

- 每 20 tick(约 8 秒)存一次 → 30 天约 900 个快照
- 每个快照 ~12KB(10 档盘口 + 3-5 方持仓)→ 总计 ~11MB
- 盘口用 `view.TopBids(10)`/`TopAsks(10)` 拷贝(和 GameSingleton.BuildSnapshot 同源)

### 2.2 交易日志(每笔成交,带身份)

```csharp
public record ReplayTrade(
    int TickIndex, decimal Price, int Qty,
    Side TakerSide, string TakerId, string MakerId);  // 身份复盘时揭示
```

- 订阅 `session.OnTradeDetailed`,每笔成交追加
- 一个关卡约 5 万~20 万笔 × ~80B → ~4~16MB
- **交易身份(TakerId/MakerId)盘中对玩家隐藏,复盘时揭示**

### 4.3 交互

- **时间轴拖拽**:拖到任意 tick → 二分查找最近快照(≤20tick 距离)→ 更新盘口/持仓/成交/独白
- **播放模式**:1x(400ms/tick)/3x/10x 自动推进
- **成交身份揭示**:每笔成交显示 TakerId/MakerId(玩家金色/AI红色/机构B紫色),盘中隐藏的博弈复盘时一目了然
- **权益曲线**:Canvas 绘制各方权益变化,当前 tick 用金色竖线标注

## 5. 二分查找快照

```csharp
public int FindSnapshotIndex(int tickIndex)
{
    // 在按 TickIndex 升序的快照列表中,找 <=tickIndex 的最后一个
    int lo = 0, hi = _snapshots.Count - 1, result = 0;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (_snapshots[mid].TickIndex <= tickIndex) { result = mid; lo = mid + 1; }
        else hi = mid - 1;
    }
    return result;
}
```

O(log N) 查找,900 个快照只需 ≤10 次比较,拖拽响应即时。

## 7. 不做的事(范围控制)

- 不做"暂停时复盘"(只在结算后)
- 不做逐 tick 精确重建(用关键帧快照,精度到 20tick≈8秒)
- 不做复盘数据导出/分享
- 不做复盘中的假设推演
