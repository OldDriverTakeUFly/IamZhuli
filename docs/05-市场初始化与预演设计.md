# 市场初始化与预演设计 v0.1 — IamZhuli

> 解决"市场初始化是假的"根本问题:玩家进场时,筹码应已在各参与者手里,
> 持仓/成本/情绪/盘口由历史行情真实涌现,而非硬编码。
> 通过"预演回放历史"实现完全真实的初始状态。

---

## 0. 设计决策摘要

| 维度 | 决策 | 理由 |
|------|------|------|
| 初始状态生成 | **预演回放历史**(散户+AI+做市商跑历史K线,玩家不参与) | 涌现式、和K线天然一致,持仓/成本/情绪全部真实 |
| 做市商 | **有限做市商**(资金/持仓有上限,会枯竭) | 盘口深度成稀缺资源,玩家学会"不够时要等或硬推" |
| 预演执行 | **加载时同步预演**(1800tick毫秒级,玩家无感) | 简单可靠 |

---

## 1. 核心问题(为什么要做)

当前开局失真三连:
1. **无限做市商**:50亿现金、10万手存货、每tick无限补单 → 玩家想买多少有多少,违背撮合制"只能吃已有挂单"本质
2. **持仓分布不真实**:散户池从零进场,AI持仓硬编码 → 真实市场里玩家进场时筹码早就在各参与者手里
3. **情绪中性**:开局恒定50 → 缺失"冰点建仓易拉升难/过热拉升易建仓难"的战略权衡

---

## 2. 预演机制(核心)

### 2.1 流程

```
关卡加载:
  1. 生成历史K线剧本(30天OHLCV,含趋势+波动)
  2. 创建市场参与者(散户池+AI+有限做市商,玩家账户但不Act)
  3. 回放历史:逐tick推进,用"价格引导"驱动参与者行为
     · 价格不是撮合产生,而是按K线剧本"引导"(见2.2)
     · 参与者根据引导价格做出真实决策(买卖/进出场/情绪变化)
     · 真实成交发生(撮合),持仓/成本/情绪/盘口涌现
  4. 预演结束 → 冻结状态即关卡初始状态
  5. 玩家进场,开始正常游戏
```

### 2.2 价格引导(关键技术点)

预演不能纯靠参与者撮合产生价格(会随机漂移,偏离K线剧本)。
需要"价格引导":一个虚拟的"市场力量"把价格推向K线目标。

实现方式:**引导做市商(GuidanceMM)**
- 预演期间,一个特殊的引导做市商根据K线剧本的目标价格,持续在目标价附近挂大单
- 它有无限资金(预演专用,结束后销毁),目的是把价格"锚定"到K线走势
- 真实参与者(散户/AI/有限做市商)在这个被引导的价格环境中做出真实决策
- 预演结束后,引导做市商的挂单全部撤销,只保留真实参与者的状态

```
K线第N天目标价 = 10.50
  → 引导做市商在 10.48~10.52 挂大量买卖单,把现价锚定到10.50附近
  → 散户看到10.50的价格,根据各自画像决策(被套的止损、便宜的抄底...)
  → 真实成交发生,散户持仓/成本变化
  → 情绪指数根据这段走势演化
```

### 2.3 预演的产出

预演跑完后,以下状态全部是真实的:
- **各参与者持仓与成本**(散户池里各画像、AI、有限做市商)
- **全局情绪指数**(由30天走势决定:下跌→冰点、上涨→过热)
- **盘口挂单**(各参与者的真实意愿单)
- **历史K线**(本来就要给的背景)
- **散户画像组成**(下跌→抄底/套牢为主、上涨→跟风为主)

## 3. 剧本系统

### 3.1 剧本定义

历史K线不能纯随机,需要**剧本驱动**。每个剧本描述一段历史走势 + 对应的市场状态:

| 剧本 | 历史走势 | 预演后情绪 | 散户状态 | 玩家体验 |
|------|----------|-----------|----------|----------|
| **下跌吸筹** | 从高位持续下跌(如12→10) | 冰点(恐慌) | 被套、止损盘多 | 建仓易(割肉多)、拉升难(没人跟) |
| **横盘磨底** | 长期窄幅震荡 | 中性偏冷 | 价投为主、观望 | 建仓中等、需打破僵局 |
| **上涨过热** | 从低位持续上涨(如8→10) | 过热(贪婪) | 跟风客多、浮盈 | 建仓难(抢筹)、拉升易(一点就着)、出货易(接盘侠多) |
| **V型反转** | 先跌后涨 | 中性偏热 | 抄底盘获利、跟风进场 | 复杂博弈 |

### 3.2 剧本与关卡的关系

- 关卡定义"玩家要做什么"(目标)
- 剧本定义"玩家进场时市场是什么样"(初始状态)
- 一个关卡可配不同剧本(增加重玩性):同一个"拉升出货"目标,在冰点和过热下体验完全不同

### 3.3 剧本的随机性

同一剧本模板 + 随机扰动:
- 趋势方向固定(如"下跌"),但斜率、波动幅度、关键拐点随机
- 每局历史K线略有不同,避免可背诵

## 4. 机构B:第二 AI 主力(兼做市)

### 4.1 定位重定义

机构B **不是被动的流动性提供者,而是第二个 AI 主力**——有自己操盘意图、会吸筹控盘、逐利的玩家级对手。它兼任基础做市职能(提供流动性),但本质是逐利对手。

游戏实际博弈结构:
- **玩家**(你)
- **AI主力A**(现有,战术型)
- **机构B**(第二AI主力,控盘型 + 基础做市)
- **散户画像池**(被收割的资源)

### 4.2 机构B的特性

- **资金规模**:流通盘的 5~20%,具体多少**由它自己判断**(评估需要多少筹码控盘)
- **控盘逻辑**:像真实主力一样,评估散户行为是否符合预期——符合则用更少筹码控盘,不符合则吸更多
- **预演中**:它也操盘(吸筹/出货),预演结束它的持仓就是开局筹码
- **做市职能**:作为副产品提供基础流动性(它挂的买卖单),但资金/持仓有限会枯竭

### 4.3 流动性的真实感

| 场景 | 旧(无限MM) | 新(机构B+三方挂单) |
|------|------------|---------------------|
| 玩家吃货 | 卖盘无限 | 卖盘=机构B+散户卖单,有限,吃光后要等或硬推 |
| 大单冲击 | 滑点小 | 滑点大(真实) |
| 盘口枯竭 | 不会 | 会(机构B资金/持仓耗尽,或散户离场) |

盘口深度是**稀缺资源**,玩家要学会算计。

## 5. 控盘机制(涌现式影响力)

### 5.1 核心思想

控盘不显式加 buff,而是通过**持仓量级自然涌现**更大的盘口影响力:
- **持仓大 → 大单更能推价**:玩家持仓30%时,一笔大买单能吃穿更多档、推升更猛
- **持仓大 → 更能引导散户情绪**:大单拉升更容易触发跟风客进场阈值、制造贪婪
- **持仓大 → 控盘感**:玩家能感受到"我说算"(挂墙能撑住、砸盘能压住)

### 5.2 落地方式

不需要新机制,而是**调参让影响力随持仓量放大**:
- 散户画像的进场触发,部分参考"近期大单成交占比"(持仓大的玩家更容易制造吸引跟风的走势)
- 机构B/AI 评估对手时,把对方的持仓量纳入博弈判断(识别"谁是控盘方")
- 玩家持仓过大会被监管盯(已是现有机制:大单成交占比)

## 6. 积分系统(收益率 + 风险调整)

### 6.1 积分定义

游戏是积分导向,**唯一目标:30天后风险调整后的收益率最大化**。

```
最终得分 = 收益率 × 风险调整系数
收益率 = (最终权益 - 初始资金) / 初始资金
风险调整系数 = f(最大回撤、波动率、监管关注值峰值)
```

### 6.2 风险调整的作用

防止"all in 一把梭"的赌徒打法:
- **最大回撤惩罚**:中途亏得多的扣分(鼓励止损、控制风险)
- **波动率惩罚**:权益曲线剧烈波动的扣分(鼓励稳健)
- **监管关注值惩罚**:操纵过激的扣分(鼓励隐蔽优雅)

这模拟真实主力的考核:**不只看赚多少,还要看赚得稳不稳、干不干净**。

### 6.3 三方对比

结算时同时展示 AI主力A、机构B 的收益率,玩家与之对比排名。
三方都在比风险调整后收益,这才是"主力收益率竞赛"。

## 7. 初始情绪的战略意义

### 7.1 情绪决定难度曲线

| 情绪 | 建仓难度 | 拉升难度 | 出货难度 | 典型策略 |
|------|----------|----------|----------|----------|
| 冰点 | ⭐ 易(割肉多、价低) | ⭐⭐⭐⭐ 难(没人跟) | ⭐⭐⭐⭐ 难(无接盘) | 隐蔽吸筹,慢牛 |
| 中性 | ⭐⭐ 中 | ⭐⭐ 中 | ⭐⭐ 中 | 标准 |
| 过热 | ⭐⭐⭐⭐ 难(抢筹、价高) | ⭐ 易(一点就着) | ⭐ 易(接盘侠多) | 快进快出,拉升出货 |

### 7.2 动态情绪的博弈

情绪不是固定的,会随玩家操作变化:
- 冰点建仓+缓慢拉升 → 情绪逐步回暖(从冰点到中性)
- 过热出货 → 情绪从狂热冷却
- 玩家可以**故意操纵情绪**(如制造波动引诱跟风,把情绪从中性推到过热,再高位出货)

这个动态过程本身就是核心博弈。

## 8. 与现有系统的对接

### 8.1 新增

- `MarketScenario`:剧本定义(历史走势生成器 + 情绪标签)
- `GuidanceMarketMaker`:预演专用引导做市商(锚定价格,预演后销毁撤单,不持筹)
- `InstitutionB`:机构B(第二AI主力,控盘型 + 基础做市,取代当前无限MM)
- `MarketPreplay`:预演执行器(回放历史,产出初始状态)
- `ScoreCalculator`:积分计算(收益率 + 最大回撤/波动率/监管值的风险调整)

### 8.2 改造

- `GameSingleton.LoadLevel`:增加预演步骤(在 loop.Start 前)
- `MarketMaker` → `InstitutionB`(从被动做市改为主动操盘的AI主力)
- `LevelDefinition`:增加剧本字段(ScenarioType);目标改为"收益率竞赛"(积分导向)
- `LevelJudge`:结算改为风险调整后收益率 + 三方对比

### 8.3 不变

- 撮合引擎、T+1、监管、图表采集、散户画像池、AI主力A 全部不变
- 预演就是"让这些系统在没有玩家的情况下跑一段历史"

## 9. 实施路径

### 阶段 1:机构B(第二AI主力,解决无限流动性)
- 新建 InstitutionB:控盘型AI + 基础做市,资金5~20%流通盘
- 它会评估散户行为、判断需要多少筹码控盘、主动吸筹/出货
- 取代当前无限 MarketMaker
- **验证**:大单吃货后卖盘会枯竭(机构B资金有限),玩家感受到滑点和深度约束

### 阶段 2:剧本系统 + K线生成
- MarketScenario:根据剧本类型生成30天OHLCV(下跌/上涨/横盘/V型)
- 验证生成的K线符合剧本特征

### 阶段 3:预演引擎
- GuidanceMarketMaker:价格引导(锚定K线目标价,预演后销毁撤单)
- MarketPreplay:回放历史,驱动散户/AI/机构B
- 预演后冻结状态(持仓/成本/情绪/盘口真实涌现)
- **验证**:预演后状态与K线一致,情绪符合剧本(下跌→冰点)

### 阶段 4:积分系统 + 三方竞赛
- ScoreCalculator:收益率 + 风险调整
- 结算展示三方收益率排名
- **验证**:不同剧本下玩家体验差异明显(冰点建仓易拉升难 等)

## 10. 待讨论问题(已精简)

已决策:机构B=第二AI主力、积分=收益率+风险调整、控盘=涌现式影响力、预演=加载时同步、初始状态=预演回放。

仍待定:
1. **引导做市商的锚定强度**:太强则参与者行为无关紧要,太弱则价格偏离K线。需实测调参。
2. **预演中机构B/AI的初始意图**:它们在预演里按什么目标决策?是否给"预演目标"(如下跌剧本里机构B低位吸筹)?
3. **预演时长**:30天×60tick=1800tick是否足够让状态稳定?可能需要更长。
4. **风险调整系数的具体公式**:最大回撤/波动率/监管值各占多少权重?需实测平衡。
