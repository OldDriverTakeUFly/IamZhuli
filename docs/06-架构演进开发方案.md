### 0.3 关键洞察(影响方案)

1. **预演复用 SimulationLoop,不新建 PreplayLoop**:用临时实例跑历史,跑完迁移账户状态,丢弃临时 loop(含 GuidanceMM 的无限资金账户)。天然隔离事件订阅。

4. **MarketMaker 替换影响面小**:直接引用仅 GameSingleton 1 处;下游读盘口深度的代码(IntentRecognizer/散户进场/AI)行为会因盘口变浅而变化,需重新调参但无需改代码。

## 2. 阶段1:机构B(第二AI主力)

### 2.1 目标
用控盘型 AI 主力取代无限做市商。盘口深度从"无限"变"有限",玩家感受到滑点和深度约束。

### 2.2 新建文件

**`src/IamZhuli.Simulation/AI/InstitutionB.cs`**
- 参考 AIMainForce 结构(IParticipant + IntentRecognizer + 状态机 + 行为模板 + Thoughts)
- 区别:
  - **控盘目标导向**:评估"需要多少筹码控盘"(基于散户行为是否符合预期)
  - **资金有限**:流通盘的 5~20%(构造参数,如 `cashRatio`)
  - **基础做市职能**:在现价附近维护基础流动性(但资金耗尽则停止)
  - **控盘状态机**:不同于 AIMainForce 的战术状态机,新增"吸筹控盘/控盘维持/控盘出货"目标层
- 复用 `IntentRecognizer`(读盘口) + 扩展 `StrategyProfile` 加 `Controlling`

### 2.3 改造文件

**`tools/IamZhuli.Web/GameSingleton.cs`**
- 第74行 `_loop.AddParticipant(new MarketMaker(...))` → 替换为 `new InstitutionB(...)`
- 删除 `SeedMarket` 相关(已删)
- `MarketMaker` ParticipantId 改为机构B的 id

**`src/IamZhuli.Simulation/Levels/LevelDefinition.cs`**
- `MarketMakerHolding` 字段语义改为机构B初始持仓(预演后会被真实涌现覆盖,POC 先保留作为机构B的 seed)

### 2.4 保留
- `MarketMaker.cs` 保留(作为"纯被动做市"工具类,未来可能有用),但不再被 GameSingleton 引用

### 2.5 验证标准
- 大单吃货后卖盘会**枯竭**(机构B资金有限),玩家感受到滑点
- 机构B 会主动操盘(吸筹/出货),不再是被动挂单
- 机构B 的 Thoughts 日志有控盘相关决策
- 现有 61 个测试不回归

### 2.6 风险
- 盘口变浅可能导致下游(IntentRecognizer/散户进场/AI)行为失真 → 需重新调参,但代码无需改
- 机构B 的"控盘判断"逻辑复杂,可能需要多轮调参

## 3. 阶段2:剧本系统

### 2.1 目标
根据剧本类型生成30天历史K线(下跌/上涨/横盘/V型),作为预演的价格引导目标。

### 2.2 新建文件

**`src/IamZhuli.Simulation/Scenarios/MarketScenario.cs`**
```csharp
public enum ScenarioType { Decline, Rally, Sideways, VReversal }

public sealed class MarketScenario
{
    ScenarioType Type { get; }
    Price StartPrice { get; }      // 历史起点(如12元)
    Price EndPrice { get; }        // 历史终点=玩家进场价(如10元)
    int Days { get; }              // 30
    decimal Volatility { get; }    // 日波动率
    /// <summary>生成每天的目标价序列(预演引导用)。</summary>
    List<decimal> GenerateDailyTargets(int? seed);
}
```
- 下跌剧本:StartPrice(12) 线性/随机衰减到 EndPrice(10),带波动
- 上涨剧本:StartPrice(8) 涨到 EndPrice(10)
- 横盘:围绕 EndPrice 震荡
- V型:先跌后涨

### 2.3 改造文件

### 2.4 验证标准

## 4. 阶段3:预演引擎(核心)

### 4.1 目标
玩家进场前,散户+AI+机构B 跑完历史K线,持仓/成本/情绪/盘口全部真实涌现。

### 4.2 新建文件

**`src/IamZhuli.Simulation/Preplay/GuidanceMarketMaker.cs`**
- IParticipant 实现
- 构造接收 `MarketScenario`(每天目标价)
- Act:按当天目标价在 ±0.02 范围挂大单(无限资金,锚定价格)
- 预演结束后随临时 loop 弃用(不迁移其账户)

**`src/IamZhuli.Simulation/Preplay/MarketPreplay.cs`**
```csharp
public sealed class MarketPreplay
{
    /// <summary>跑预演,产出初始状态。</summary>
    public PreplayResult Run(MarketScenario scenario, LevelDefinition level)
    {
        // 1. 创建临时 loop(同一 MarketRules/Stock)
        // 2. 添加参与者:散户池+AI+机构B+GuidanceMM+MarketDataCollector
        //    (玩家账户不 AddParticipant,但可预创建)
        // 3. 按 scenario 的日目标价,逐天跑 ticksPerDay 个 tick
        //    · 每天 GuidanceMM 锚定当天目标价
        //    · 散户/AI/机构B 在被引导的价格环境里真实决策
        // 4. 跑完,迁移状态到游戏 loop:
        //    · 各参与者账户的 Cash/Position(直接复用同一 Session?或迁移)
        //    · MarketDataCollector 的 DailyCandles/PreviousClose
        //    · 情绪指数(MarketSentiment)
        // 5. 弃用临时 loop(含 GuidanceMM 账户)
    }
}
public sealed class PreplayResult
{
    List<DailyCandle> HistoryCandles;
    decimal PreviousClose;
    decimal InitialSentiment;
    // 参与者状态通过共享 Session 直接迁移(见4.3)
}
```

### 4.3 关键设计:状态迁移方式

**方案A(推荐):预演和游戏共用同一个 TradingSession/MatchingEngine**
- 预演用临时 SimulationLoop,但 Session/Engine 是游戏 loop 的同一个实例
- 预演跑完,参与者账户状态天然就在 Session 里(无需迁移)
- 只需迁移:MarketDataCollector 的数据(用预演的 collector)、情绪指数
- 丢弃临时 loop(含 GuidanceMM,它的账户留在 Session 但不再 Act)

**方案B:独立 Session,跑完迁移账户**
- 更隔离但迁移复杂(要深拷贝账户状态)
- 不推荐

### 4.4 改造文件

**`tools/IamZhuli.Web/GameSingleton.cs` — LoadLevel 拆分**
```csharp
void LoadLevel(LevelDefinition level)
{
    // ... 重置状态
    BuildMarket(level);           // 构建 Engine/Loop/Session/参与者(不含 GuidanceMM)
    MarketPreplay.Run(loop, scenario, level);  // 预演(临时驱动,玩家不Act)
    WireRuntimeCallbacks();       // 接线监管/权益采集/失败判定(预演后才接)
    loop.Start();                 // 玩家可操作
}
```

### 4.5 验证标准(最关键)
- 预演后散户持仓/成本真实(下跌剧本→散户被套成本高)
- 情绪符合剧本(下跌→冰点<30、上涨→过热>70)
- 盘口有真实挂单(各参与者意愿单)
- 历史K线显示在图表背景
- 玩家进场即面对真实市场状态

### 4.6 风险
- 引导做市商强度调参(太强→参与者行为无关,太弱→价格偏离K线)
- 预演时长(1800tick)的性能(毫秒级,应无问题)
- 共享 Session 方案下 GuidanceMM 账户残留(不影响,它不 Act)

## 5. 阶段4:积分系统

### 5.1 目标
风险调整后收益率作为唯一胜负标准,三方(玩家/AI/机构B)对比排名。

### 5.2 新建文件

**`src/IamZhuli.Simulation/MarketData/EquityCurveCollector.cs`**
- 仿 MarketDataCollector,订阅 loop.OnTick/OnNewDay
- 每 tick/每日用 Engine.LastPrice 对玩家、AI、机构B 算 TotalEquity
- 维护三方权益序列 `List<decimal>`
- 暴露:最大回撤、波动率、当前收益率

**`src/IamZhuli.Simulation/Levels/ScoreCalculator.cs`**
```csharp
public sealed record ScoreResult(
    decimal ReturnRate,           // 收益率
    decimal MaxDrawdown,          // 最大回撤
    decimal RiskAdjustedScore,    // 最终得分
    int Rank,                     // 三方排名(1=第一)
    string Comment);              // AI教练评价

public sealed class ScoreCalculator
{
    ScoreResult Calculate(Account player, Account aiA, Account institutionB,
                          EquityCurveCollector curves, Regulator regulator,
                          decimal initialCash, Price? lastPrice);
}
```
- 收益率 = (最终权益 - 初始) / 初始
- 风险调整 = 收益率 × (1 - 最大回撤×权重 - 波动率×权重 - 监管峰值×权重)
- 三方对比:对 AI/机构B 也算同样得分,排名

### 5.3 改造文件

**`src/IamZhuli.Simulation/Levels/LevelJudge.cs`**
- `Settle` 的目标制三星(第103行)替换为调 `ScoreCalculator`
- `LevelResult` 扩展 Score/Rank 字段
- `EvaluateProgress` 改为返回收益率/回撤等实时指标(替代目标进度)

**`tools/IamZhuli.Web/GameSingleton.cs`**
- 持有 EquityCurveCollector(订阅游戏 loop)
- EndLevel 调 ScoreCalculator
- 快照加实时收益率/回撤/排名

**`tools/IamZhuli.Web/Dtos.cs` + 前端**
- 结算页改为收益率+排名展示
- 实时面板加收益率/回撤

### 5.4 验证标准
- 结算显示三方收益率排名
- 最大回撤大的得分低(风险调整生效)
- 不同剧本下得分差异合理

## 6. 跨阶段的调参点(实施后必做)

机构B替换+预演接入后,盘口深度变化会导致下游行为变化,需要重新调参:
- `IntentRecognizer`:深度失衡阈值(盘口变浅,失衡更易触发)
- `RetailProfilePool`:进场参考深度的逻辑
- `AIMainForce`:Defend/Follow 的深度判断
- `Regulator`:大单/波动阈值(盘口浅→大单冲击更明显)
- `InstitutionB`:做市补单量/资金规模(核心调参)

## 9. 待确认的工程细节

1. **预演的 Session 共享**:方案A(共享Session) vs 方案B(独立迁移)。倾向A,但需确认 GuidanceMM 账户残留无害。

4. **风险调整权重**:最大回撤/波动率/监管值各占多少。需实测平衡。
5. **预演性能**:1800tick 的同步预演是否影响加载体验(预期毫秒级,需实测)。
