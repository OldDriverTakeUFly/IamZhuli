# 开发计划与技术选型 v0.1 — IamZhuli

> 第一期 POC 的里程碑划分、技术选型、开发顺序。设计依据见 `docs/01-游戏设计文档.md`,规范见 `docs/02-开发规范.md`。

---

## 0. 总体策略

**核心原则:从"游戏大脑"开始,先让它好玩,再套皮肤。**

1. **纯 C# 类库起步**——撮合引擎、参与者、AI、监管、时间逻辑做成可单元测试的类库,**完全不碰 Unity**。
2. **命令行模拟器验证可玩性**——做一个 `SimCli` 工具,无 UI 跑关卡,打印盘口/成交/AI 决策到终端。能在几秒内验证"散户参数对不对、AI 会不会博弈"。
3. **Unity 做表现层**——大脑验证好玩后,Unity 工程只负责把状态渲染成盘口 UI、处理输入。
4. **每一步都可验证**——每个里程碑结束都有"能跑、能看"的产出,不积累大爆炸式风险。

## 1. 技术选型(已定)

| 项 | 选择 | 说明 |
|----|------|------|
| 逻辑层框架 | **.NET 8 类库** | LTS,可单元测试,后期可被 Unity 引用 |
| 单元测试 | **xUnit** | .NET 主流 |
| 表现层引擎 | **Unity 6 LTS**(后期) | 仅做 UI/渲染/输入 |
| 订单簿数据结构 | **`SortedDictionary<decimal,PriceLevel>` + 每价位 `Queue<Order>` + `Dictionary<id,Order>` 撤单索引** | 标准教科书结构,够快好调试 |
| 货币类型 | **`decimal`**(价格建议封装 `Price` 值类型) | 绝不用浮点算钱 |
| 关卡/复盘数据 | **System.Text.Json** | 序列化关卡配置与回放快照 |
| 日志 | **Microsoft.Extensions.Logging** | 标准、可移植 |
| 命令行模拟 | **IamZhuli.SimCli**(控制台程序) | 验证可玩性的关键工具 |
| AI 框架 | **自研轻量状态机 + 意图识别评分** | 不引外部行为树库,逻辑可控可测 |

### 1.1 为什么不引外部撮合/AI 库

- 撮合引擎核心就两三百行,自写比改造别人库更可控、更好调试,且能精确控制游戏所需语义(T+1、涨跌停、对倒识别等)。
- AI 是游戏性核心,自研状态机能精确调参、能在复盘里输出"内心独白"(外部库做不到)。

### M1 — 撮合引擎(核心物理基础)

> 这是整个游戏的物理基础,错了游戏就崩,必须可测。

**任务**:

1. **核心类型**(`IamZhuli.Core`):
   - `Price`(值类型,封装 `decimal`,提供比较/运算)。
   - `Quantity`(`int`,手)。
   - `OrderId`、`ParticipantId`。

2. **订单模型**(`IamZhuli.Engine`):
   - `Order`:类型(限价/市价)、方向(买/卖)、价格、数量、已成交数量、状态(待成交/部分成交/已成交/已撤)、时间戳、所属参与者。
   - `Side` 枚举(Buy/Sell)、`OrderType`(Limit/Market)、`OrderStatus`。

3. **订单簿**(`OrderBook`):
   - 买盘 `SortedDictionary<Price, PriceLevel>`(价格降序,最优买价在前)。
   - 卖盘 `SortedDictionary<Price, PriceLevel>`(价格升序,最优卖价在前)。
   - `PriceLevel` 内部 `Queue<Order>`(时间优先)。
   - `Dictionary<OrderId, Order>` 撤单索引(O(1) 撤单)。

4. **撮合逻辑**(`MatchingEngine`):
   - 新订单进入:限价单挂簿或立即成交(若穿过对方最优价);市价单吃穿对方多档。
   - 成交价 = 被动方价格;现价 = 最近成交价。
   - 边吃边累加 `Σ(价×量)/总量` 得加权均价,产出逐笔 `Trade`(成交记录)。
   - 涨跌停约束:到达涨跌停价后,该方向禁止开仓(只允许平仓)。

5. **T+1 规则**(部分在引擎,部分在账户层):当日买入筹码标记"T 日不可卖”,次日解锁。POC 在账户层实现持仓的 T+1 锁定。

6. **单元测试**(全覆盖,这是 M1 的硬指标):
   - 限价单挂簿排队、价格优先时间优先。
   - 限价单立即成交(穿价)。
   - 市价单吃穿多档、加权均价正确、逐笔 Trade 正确。
   - 撤单(部分成交后撤、挂簿中撤)。
   - 涨跌停阻止开仓。
   - 卖盘空时市价买单剩余处理。

**完成标准**:撮合引擎单元测试 100% 核心路径通过;能精确还原设计文档第 2.5 节"吃货推价"的数值例子。

### M2 — 时间系统与玩家账户

**目标**:时间能流动(tick 循环),玩家能下单,一个"只有玩家"的市场能跑起来。

**任务**:

1. **时间系统**(`IamZhuli.Simulation`):
   - `Tick` 为最小推进单位;`SimulationClock` 管理当前 tick、当前交易日(1-30)、日内阶段(盘前/竞价/午休/盘后)。
   - 一个交易日 = 约 300 tick(可配)。30 天 = 一个关卡。
   - 日间一键跳过(进下一交易日盘前)。

2. **玩家账户**:
   - 持仓(含 T+1 锁定:今日买入标记为 `_t1Locked`,次日开盘解锁)。
   - 现金、可用现金、浮盈浮亏。
   - 下单接口:限价买/卖、市价买/卖、撤单。
   - 下单校验:资金够不够、持仓够不够(且未 T+1 锁定)。

3. **tick 循环**(`SimulationLoop`):
   - 每 tick:撮合引擎处理所有待成交订单 → 更新现价 → 产出成交 → 推进时间。
   - 暴露事件:`OnTick`、`OnTrade`、`OnPriceChange`,供表现层/SimCli 订阅。

4. **SimCli M2 版**:命令行驱动,玩家可手动下单,每 tick 打印五档盘口和最新成交。

**完成标准**:SimCli 里手动下单,看到盘口逐档跳动、成交明细、持仓/资金变化、T+1 锁定生效。

---

### M3 — 散户群体(市场弹性) ✅

**实际实现**:从原定"4 群体聚合模型"重设计为**画像池模型**(每画像独立账户、异质化参数、动态进出)。详见 `docs/04-散户系统重设计.md`。

**9 种画像**(`src/IamZhuli.Simulation/Participants/RetailV2/`):
- 激进/温和跟风客、价值投资者(金字塔分批建仓)、恐慌止损者、抄底猎手、投机客、羊群效应型、消息驱动型(预留)、超跌反弹客(看乖离率博反抽)。

**核心特性**:
- 每画像独立账户,异质化的止盈/止损敏感度(投机客 3%止损/1.2x止盈,价投不止损)。
- 多维情绪驱动(贪婪/恐惧 + 信心 + 群体热度 + 消息偏差)。
- 趋势感知刷新:涨势多刷跟风客,跌势多刷抄底者。
- 被动资金流(PassiveFlow):无视涨跌的底盘买盘,保证阴跌不死锁。

**完成标准**(已达成):盘口呈现有涨有跌、群体行为可辨的自然形态;阴跌有抄底盘+被动流承接,拉升有获利盘止盈卖压。

### M4 — AI 主力(真正的对手) ✅

**目标**:有会博弈的 AI 主力对手。

**实际实现**:从原定"1 个对手"扩展为**双 AI 对手**:
- **AIMainForce**(`AI/AIMainForce.cs`):状态机(观察/护盘/洗盘/出货/跟风/反杀)+ 意图识别器,对玩家操作做出有意义的、非随机的反应。
- **InstitutionB**(`AI/InstitutionB.cs`):合三为一(做市+风险控制+操盘),取代无限做市商。低风险正常做市,高风险收紧深度+管理敞口,极高风险转为方向操作。高位获利了结+亏损纪律止损。

**任务**:

1. **意图识别器**(`IamZhuli.AI`):
   - 监测盘口信号,为每个意图(吸筹/推价/对倒/挂墙)算置信度。
   - 信号:持续同价位买单、短时大单拉升+放量、对倒特征、反复挂撤大单。

2. **状态机**:
   - 状态:观察/护盘/洗盘/出货/跟风/反杀。
   - 状态切换由意图识别 + 自身持仓成本 + 价格水平驱动。
   - 每状态对应一套行为模板(挂单/吃单/撤单策略)。

3. **AI 账户**:与玩家账户同构,有自己的持仓/成本/资金,持仓对玩家不可见。

4. **AI 个体属性**:策略偏好(激进/保守/狡猾)、反应灵敏度(随难度提升)。

5. **SimCli M4 版**:观察 AI 行为——玩家拉升时 AI 跟风后提前跑,玩家洗盘时 AI 反向护盘吸筹。

**完成标准**:AI 能对玩家操作做出有意义的、非随机的反应;能识别明显操纵并反制。

---

### M5 — 监管与关卡

**目标**:一整关可玩,有目标、有约束、有评分。

**任务**:

1. **监管**(`IamZhuli.Regulator`):
   - 关注值监测:对倒/虚假挂单/异常波动/频繁撤单/大单占比。
   - 惩罚阶梯:30%问询 → 60%罚款 → 80%立案 → 100%强平失败。
   - 关注值衰减。

2. **关卡配置**(数据驱动,JSON):
   - 股票(内在价值、流通盘、历史价)、目标、约束(资金/时间/监管红线/成本)、难度参数(AI/散户/事件频率)、剧本事件时间表。

3. **目标判定**:拉升到位、出货比例、护盘维持等目标的达成判定。

4. **三星评分**:基础达成 + 效率 + 操纵优雅(监管值低位)。

5. **重试**:重置全部状态到关卡初始。

6. **SimCli M5 版**:跑完一整关,输出是否达成、评分、关键节点。

**完成标准**:能跑通至少一个完整关卡(如"拉升出货"),有明确的成败与三星评分。

---

### M6 — 复盘系统 ✅

**目标**:关卡结束后能回看整个博弈过程。

**实际实现**:详见 `docs/07-复盘系统设计.md`。
- **ReplayCollector**:每 20 tick 存关键帧快照(盘口10档+各方持仓+现价+监管值)+ 订阅 OnTradeDetailed 存全部交易日志(带买卖双方身份)。
- **前端复盘 UI**:全屏 modal,时间轴拖拽回放,播放模式(1x/3x/10x),成交身份揭示(TakerId/MakerId 颜色标识),AI/机构独白按 tick 过滤,权益曲线 Canvas 绘制。
- 内存预算:~900 快照×12KB + ~10万交易×80B ≈ 19MB/关卡。

**完成标准**(已达成):复盘能清晰回放"AI 当时在干什么、为什么",验证 AI 真的在博弈而非随机。

---

### M7 — 表现层(Web) ✅

**目标**:人能坐着玩通一关的真正游戏。

**实际实现**:从 Unity 改为 **ASP.NET Core Web 方案**。
- **SignalR** 实时推送快照+成交;REST 端点处理下单/撤单/关卡切换/消息发布。
- **lightweight-charts v5** 渲染分时图/日K线;Canvas 绘制筹码峰/权益曲线。
- 功能:盘口五档、下单+主力挂单列表(单撤/全撤/撤买撤卖/点击改价)、分时/日K/筹码联动、监管条、多维情绪温度计、关卡选择、盘前自由探索、盘后消息操作、三方积分结算、复盘模式。
- 时间:150 tick × 400ms = 1 分钟/天,30 天关卡约 30 分钟。

**完成标准**(已达成):浏览器中能玩通完整一关,体验符合设计文档的核心体验。

## 5. 开发顺序与依赖

```
M0 (环境骨架)
  └─ M1 (撮合引擎)  ← 一切的基础,优先级最高
       └─ M2 (时间+玩家账户)
            ├─ M3 (散户)  ─┐
            └─ M4 (AI主力) ─┴─ M5 (监管+关卡) ─ M6 (复盘)
                                                 └─ M7 (Unity 表现层)
```

- M1 是绝对优先,撮合错了后面全错。
- M3/M4 可并行,但都依赖 M2。
- M6 依赖 M4(AI 内心独白需要 AI 决策记录),但可在 M5 后做。
- M7 是最后阶段,但 M2 后即可开始做最简 UI(单参与者盘口),不必等大脑全完成——可并行验证。
