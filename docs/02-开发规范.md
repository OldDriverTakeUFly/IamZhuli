# 开发规范 v0.1 — IamZhuli

> 本项目(agent 与人类协作者共同)的技术约定。动手写代码前请先读此文件。

---

## 1. 架构总则:逻辑/表现分离

```
┌─────────────────────────────────────────┐
│  表现层 (Unity, 后期接入)                │
│  UI / 渲染 / 输入 / 动画 / 音效          │
│  只读核心状态, 调用核心 API              │
└──────────────────┬──────────────────────┘
                   │ (接口/事件, 无反向依赖)
┌──────────────────▼──────────────────────┐
│  逻辑层 (纯 C# 类库, 可单元测试)         │
│  撮合引擎 / 参与者 / AI / 监管 / 时间 / 规则 │
│  零 Unity 依赖                           │
└─────────────────────────────────────────┘
```

**铁律**:
- 逻辑层**绝不引用** `UnityEngine`。
- 表现层通过**接口和事件**与逻辑层交互,逻辑层不反向依赖表现层。
- 逻辑层的状态变更对外通知用**事件/回调**(C# event 或 IObservable),不直接调 UI。

> 好处:逻辑层能用 `dotnet test` 单元测试、能用命令行跑模拟验证"好不好玩"、Unity 后期接入只是"套皮肤"。

## 2. C# 技术栈

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | C# 12+ | 现代 C# |
| 目标框架 | .NET 8 (LTS) | 长期支持、性能好 |
| 单元测试 | xUnit | .NET 主流,生态成熟 |
| 断言风格 | FluentAssertions(可选) | 可读性好 |
| 日志 | Microsoft.Extensions.Logging | 标准、可移植到 Unity |
| 序列化(关卡/复盘) | System.Text.Json | 标准库,性能好 |

> 注:逻辑层用 .NET 8 类库。后期接入 Unity 时,Unity 6 支持 C# 9 级别 + 部分 C# 12 特性,需注意特性兼容性;关键逻辑尽量用保守语法以保证跨 Unity 编译。

## 3. 命名与代码风格

| 元素 | 风格 | 示例 |
|------|------|------|
| 类、方法、属性 | PascalCase | `OrderBook`, `MatchOrder()` |
| 局部变量、参数 | camelCase | `remainingQty`, `avgPrice` |
| 私有字段 | `_camelCase` | `_bids`, `_orderIdSeq` |
| 接口 | `I` 前缀 | `IMatchingEngine` |
| 常量 | PascalCase | `MaxTickSize` |

### 货币与数量(关键)

- **所有金额/价格用 `decimal`,绝不用 `double`/`float`。**
- 价格建议封装为 `Price` 值类型(强类型,防止单位混用),内部 `decimal`。
- 数量(手/股)用 `int` 或 `long`(游戏量级 `int` 足够)。
- 单位约定:**价格单位"元"**,最小变动 0.01;**数量单位"手"**(1 手 = 100 股);**金额单位"万元"**(显示层用,内部仍用 decimal 元)。

## 5. Git 提交规范(启用 git 后)

采用 Conventional Commits,scope 用英文,描述用中文:

```
<type>(<scope>): <中文描述>

type:  feat | fix | refactor | test | docs | chore | build
scope: engine | ai | retail | regulator | time | ui | docs | ...
```

示例:
- `feat(engine): 实现订单簿限价单撮合`
- `test(ai): 补充意图识别状态切换测试`
- `docs: 更新时间系统设计`

---

## 6. 测试约定

- **撮合引擎必须有 100% 核心路径覆盖**:限价单成交、市价单吃穿多档、撤单、价格优先时间优先、涨跌停、T+1。
- **AI 决策用行为测试**:给定盘口状态,断言 AI 进入正确状态、做出合理决策。
- 测试命名:`MethodName_Scenario_ExpectedResult`,如 `MatchOrder_MarketBuyCrossesMultipleLevels_ReturnsWeightedAvgPrice`。
- 测试项目结构镜像源码:`tests/IamZhuli.Engine.Tests/` 对应 `src/IamZhuli.Engine/`。
