# Agent 图形化测试 SOP(三Agent体系)

> 服务: http://localhost:5023 (先 `dotnet run`)。执行: `node tools/playtest/<agent>.mjs`
> 产物: /tmp/playtest/<agent>-report.json (+截图)

## 总体分层

| Agent | 职责 | 对象 | 通道 |
|-------|------|------|------|
| QA-1 标准功能 | 需求/设计文档符合性验收 | docs/01,07,08,09 的规则数字 | 黑盒API(不读代码) |
| QA-2 安全越界 | 恶意输入/状态越界/并发竞态 | HTTP接口+状态机 | API轰炸 |
| QA-3 可玩性 | 玩家体验量化 | 浏览器真实游玩 | Playwright画像 |

与 xUnit 的关系: xUnit 是白盒(开发者视角,247个);Agent层是黑盒——
覆盖路由/序列化/信号量/前端链路,回答"交付物是否符合文档承诺"。

## QA-1 标准功能测试 (qa-functional.mjs)

**依据文档 → 提取可验证数字 → 逐项黑盒断言。**

### SOP
1. 从 docs/ 提取功能清单(卡牌定义/12段结构/监管阈值/交易规则),登记为检查点表
2. 每检查点: 准备场景(API) → 操作 → 断言响应与后续快照
3. 结果分三档: PASS / DEVIATION(行为与文档不符) / UNDOC(文档未覆盖的行为)

### 检查点基线(编号入报告)
- F01 预演: 选关后历史日K=30根,昨日筹码快照存在
- F02 一天12段: 阶段名序列=盘前申报/盘前竞价/盘中×8/尾盘申报/收盘竞价
- F03 申报段不撮合(揭牌量0),锁单段撤单牌作废
- F04 开盘价=盘前竞价首笔成交;收盘价=收盘竞价价(静默日切)
- F05 能量: 起始3,每段+3,上限10
- F06 每段出牌≤2张(第3张明确报错)
- F07 架势牌: 1费,不占2张限额,同段可替换
- F08 T+1: 当日买入持仓全部锁定(available=0),次日解锁
- F09 涨跌停±10%: 竞价价不越界
- F10 券池=流通盘20%(40000/200000)
- F11 监管阶梯: 关注值→None/Inquiry(30)/Warning(60)/Investigation(80)/失败(100)
- F12 信息战: 警示=辟谣+水军捣毁+罚50万;立案=封口1天
- F13 消息: 盘后可发/盘中拒,扣成本
- F14 结算: /api/score 三方排名
- F15 复盘: /api/replay 含快照/成交/事件/筹码

### 通过标准
全部PASS或DEVIATION有书面豁免;新UNDOC项需回写文档(文档即契约)。

## QA-2 安全与越界测试 (qa-security.mjs)

**每个用例断言三件事: 不500(可控错误)、不留脏状态(可继续正常玩)、不越界值(负数/NaN/超界)。**

### SOP
1. 输入域扫描: 每个API参数取 {非法类型,越界值,空值,极值} 笛卡尔抽样
2. 状态机攻击: 非法时序(Waiting态全端点/非Play出牌/重复begin/连点endturn/并发play+endturn)
3. 经济攻击: 透支买/无券做空/无空头平仓/负数量/巨量单
4. 每轮攻击后: 健康检查(loadlevel重建→正常出牌→揭牌)验证可恢复

### 用例基线
- S01 handIndex: -1 / 99 / "abc" / null
- S02 deck: [] / 31张 / 未知牌名 / 重复30张同名
- S03 qty: 0 / -100 / 1e9 / 1.5(小数)
- S04 price: 0 / -1 / 超涨停×2 / "10.0a"
- S05 news/signal: 未知类型字符串 / 超长字符串
- S06 Waiting态: 全端点调用(应可控拒绝)
- S07 重复/并发: endturn×3连发 / play与endturn交错
- S08 深夜路径: skipday在盘中 / nextday在盘中 / retry双击
- S09 长局资源: 连续3天完整循环后replay/chips可正常拉取

### 通过标准
零500(可4xx)、零负值/NaN泄漏、每轮攻击后健康检查通过。

## QA-3 可玩性测试 (qa-playability.mjs)

**模拟玩家画像真实游玩,量化"节奏"与"信息可达性"。**

### SOP
1. 画像A"新手乱点": 冷启动,每段随机点1-2张可见牌+结束回合,玩6段
2. 画像B"理性策略": 能量攒满段才出双牌(操盘+架势),玩6段
3. 每段自动记录:
   - 点击数/滚动需求(核心循环是否同屏)
   - 操作反馈延迟(点击→UI变化ms)
   - Resolve等待时长 vs 操作时长(节奏比)
   - 段末状态变化量(操作有效性)
4. 同屏信息检测: 价格/手牌/能量/监管四要素在视口内的比例
5. 体验日记: 每段一行"看到了什么→做了什么→结果"

### 指标基线(参考值)
- 单段操作≤4次点击;核心循环(图+手牌)同屏≥90%视口设备
- 点击反馈<800ms;Resolve等待≤15s/段
- 每段至少1项状态变化(价格/持仓/能量/消息)

### 产出
可玩性评分(上述指标达成率)+痛点清单(按影响排序)。
